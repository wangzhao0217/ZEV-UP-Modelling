# Data, provenance and reproduction scope

All model volumes are daily **car-person trips**, including retained routes at
or below 3 km. The public capacity calculation converts eligible, purpose-weighted
volume to vehicle demand using purpose-specific occupancy. It pools origin and
destination demand at shared physical charging locations. AP eligibility,
charging access, purpose weighting and capacity remain separate operations.

## Data dictionary

| Directory | Unit and role |
|---|---|
| `flows/` | One row per routed synthetic observation: `flow_id`, production group `origin`, `purpose`, joined `origin_oa`, `vol`, routed `d` (km), post-jitter `euclidean_km`, recovered pre-jitter `gravity_distance_km`, `ap`, `home_score`, purpose weight `w`, vehicle `occupancy`, binary public access `P_i/P_j`, and zero-based origin/destination station positions (`-1` means no accessible station) |
| `stations/` | Ordered regional physical sites; `station_position`, `N_points` (missing counts conservatively represented as zero), `ocm_id`, `point_count_missing` |
| `areas/` | Exact frozen 2022 OA scores and geometry; key `geo_code`; AP and home-charging scores are in [0,1]. Census counts, component scores and CRS metadata are retained |
| `charging/` | Canonical 2022 OA charging diagnostics and geometry; scores describe area access and local density, separately from flow capacity |
| `parameters/` | Scoring configuration, signed negative gravity coefficients (km^-1), occupancy assumptions, vehicle-price proxies, annualised earnings references and census column mappings |
| `validation/` | Frozen OA AP, households and affordability; full OA/DZ/IZ lookup; observed numeric 2025 Q4 private-BEV counts. Missing/suppressed counts are absent, never zero-filled |
| `postcode/` | Aggregate postcode score sums, MOT cohort/price counts, property values and OA/postcode intersection scores. No vehicle IDs or vehicle-level records |
| `thresholds/` | Frozen OA household/demographic inputs; matched Data-Zone house-price and BEV inputs; postcode price-segment counts |
| `assessments/` | Vehicle component factors in the row order of `study_oa_inventory.csv`; retained component-grid outputs and the actual 200-setting geographic design |
| `maps/` | Cached vector basemaps, regional boundaries and the retained charging-location snapshot |
| `reference/` | Expected final result tables, used only for comparisons and fixed non-trip summary metadata |

Individual source filenames, transformations and checksums are in
`provenance.json`; package checksums are in `manifest.json`. Numerical comparisons
use explicit tolerances for floating-point calculations. File checks use exact
SHA-256 equality. Package integrity is not itself a scientific reproduction check.

## What is reproduced

The default command recomputes national, regional and purpose-level screening,
shared-site capacity, alternative AP screens, all final sensitivity families,
chaining losses, circuity diagnostics, observed-support DZ/IZ correlations,
postcode regressions, demographic/price/BEV threshold diagnostics and their
cross-validation, the vehicle-assignment grid and the twelve-purpose robustness
experiments. Executable manuscript code computes area summaries, statistical
figures and tables from the supplied scores/geometry and regenerated outputs.

The data begin at frozen model inputs and aggregate statistical inputs. Frozen
AP/HCF scores, synthetic route support, regional vehicle-mix proportions and
source spatial joins are inputs, not newly estimated or independently validated.
The parent pre-jitter distance is recovered using the archived integer child
multiplicity before distance-decay reweighting. No trip volumes or eligibility
rules are altered by packaging.

The default run also recomputes the 25-setting AP membership grid and verifies
the rounded 93% minimum stability under one-edge shifts of 0.05. The routing
footnote's correlation and median differences are recalculated from the retained
14 matched route-distance pairs; route matching and Google API calls are not
repeated. Original matching code is included without API credentials or route
geometry.

The cutoff calibration in Appendix B.4 has retained comparison tables, 1,000
bootstrap draws and its original source code. Its exact original 84-row input
snapshot is unavailable: the regional files now present produce different
pseudo-label boundaries. The default run verifies the reported confidence
intervals from the saved draws but does not claim to refit that calibration.
The selected 0.523/0.797 class cutoffs are supplied model parameters.

The other reported component grids (1–3 and 5–7) have retained outputs and source
in `assessments/archived/` and `scripts/source_preparation/component_grids.qmd`.
Their original fits are not certified as fully regenerated by the default run.
The command does recompute their row counts, selected summaries, coefficients
of variation and invariance checks from retained sweeps, writing
`results/assessments/component_grid_summary.json`.
In particular, the geographic grid's saved invariant regression is not recovered
by its separate diagnostic join. Its 200 retained settings are supplied because
the original Python random state was not recorded. No missing fit is invented.

One reporting discrepancy remains: the manuscript's Grid 2 deviation range is
0.53–0.68, while the full retained 56-row `grid2_yougov_validation.csv` spans
0.519781–0.702507. The package preserves the source manuscript and reports the
actual archived range. A different intended subset would need to be identified
before claiming that the printed range has been reproduced.

Static maps, the framework, vehicle illustrations and the SPT biplot are archived
manuscript assets. Spatial inputs and figure sources accompany them; default
rendering reuses those assets and does not certify regeneration of their pixels.

## Limits of a complete upstream rebuild

The original `EV_od/inputdata/DataZones.Rds`, `grid_scot.Rds` and `oas.Rds` were
not present at their recorded paths when packaging. They hold population controls,
the destination grid and jitter subpoints. Exact regeneration also requires the
original authorised POIs, the prepared routing graph, the original scoring/input
versions, and the relevant sampling environment. The included upstream code is
reference source using its original layout; it is not the portable default run.
The frozen downstream inputs make the supported analyses runnable independently.
